# TidyDock 产品体验优化建议

日期：2026-07-05

## 判断

TidyDock 当前方向正确：轻量、本地、手动整理、低资源占用。下一阶段不建议继续扩张功能边界，优先补齐“首次使用、日常管理、异常恢复、复杂背景可读性”四个用户感知最强的环节。

## 依据

本次审视基于项目文档、当前真实配置、源码入口和本地截图。

| 依据 | 结果 |
| --- | --- |
| Release 构建 | 通过，0 warning，0 error |
| portable 打包 | 通过 |
| portable 启动烟测 | 通过 |
| 空闲短测 | private memory 约 15.68 MB，CPU 秒数稳定 |
| 真实配置 | 已包含系统位置、应用、分隔符、多个文件夹、分组、自定义图标 |
| 截图目录 | `src/TidyDock.WinForms/dist/review-screens/` |

## 截图观察

| 界面 | 观察 |
| --- | --- |
| Dock 默认态 | 图标风格统一，玻璃底座轻巧；复杂壁纸下边界感偏弱。 |
| Dock 右键菜单 | 功能可达，但菜单字号和视觉层级偏系统默认，和 Dock 玻璃风格割裂。 |
| 设置页 Dock 项区域 | 信息完整，但目标路径过长，按钮数量多，主次不够明确。 |
| 设置页底部 | 草稿状态存在，但“预览 / 确定”对普通用户不够行为化。 |
| 文件夹 Flyout | 分组展示清楚，是当前最接近成熟体验的界面。 |
| 分组管理窗口 | 功能完整，但大列表缺搜索、筛选和更明确的批量状态反馈。 |

## P0 建议

| 方向 | 问题 | 建议 |
| --- | --- | --- |
| 首次使用 | 空 Dock 或新用户不一定知道从哪里开始。 | 空 Dock 显示三个入口：`添加应用/文件`、`添加文件夹`、`打开设置`。 |
| 产品一致性 | 文档仍强调“编辑模式”，但 WinForms 当前是右键和设置页直接管理。 | 统一为“右键快速管理 + 设置页批量管理”，删除或弱化编辑模式叙事。 |
| 误操作 | 右键“移除”立即执行，用户可能误删 Dock 配置。 | 移除前确认：`从 Dock 移除，不会删除原文件`。后续可做撤销。 |
| 异常恢复 | 目标不存在时只弹路径错误，用户没有恢复路径。 | 增加损坏项视觉状态，并提供 `重新定位目标`。 |
| 设置保存 | “预览 / 确定”理解成本偏高。 | 改为 `预览到 Dock`、`保存并关闭`，底部状态保留。 |

## P1 建议

| 方向 | 问题 | 建议 |
| --- | --- | --- |
| 右键菜单 | 菜单混合全局添加和单项操作。 | 分组：单项操作在上，全局添加在下；单项操作补 `重命名`、`更换图标`、`打开方式`、`管理分组`。 |
| Dock 可读性 | 复杂壁纸下玻璃底座边界偏弱。 | 增加 `底座强度` 或 `增强对比度` 开关；默认随透明度保持更稳定的边缘和阴影。 |
| 设置页按钮 | Dock 项区域按钮过多，视觉权重接近。 | 保留一个主按钮，其他折叠为次级按钮组；危险操作固定靠右。 |
| 路径展示 | 表格目标列长路径占据过多注意力。 | 默认显示短路径或文件名，完整路径放 tooltip；损坏路径用警示色。 |
| 文件夹 Flyout | 顶部完整路径占位较强，按钮含义依赖图标。 | 标题下改为项目数或短路径；返回、资源管理器、关闭加 tooltip。 |
| 分组管理 | 大列表管理成本高。 | 增加搜索框、`只看未分组`、`只看当前分组` 筛选。 |

## P2 建议

| 方向 | 建议 |
| --- | --- |
| 图标管理 | 一键圆角和逐项圆角已经可用，后续只需补“预览变化”，不建议继续复杂化样式系统。 |
| 备份恢复 | 导入备份进入草稿是正确方向；建议在成功提示里明确 `还需预览或保存才会生效`。 |
| 托盘菜单 | 保持轻量即可；可补 `打开设置`、`显示/隐藏 Dock`、`退出` 三项优先级，不要塞入全部管理功能。 |
| 文档 | 用户指南需要同步 WinForms v0.2 的真实流程，尤其是右键菜单、设置页草稿、备份导入。 |

## 不建议做

| 方向 | 原因 |
| --- | --- |
| 运行中小圆点 | 会把产品推向任务栏替代品，偏离边界。 |
| 最近应用 / 最近文件 | 需要记录行为或扫描，和本地轻量、可解释方向冲突。 |
| 自动桌面整理 | 会改变用户文件结构，风险高。 |
| 文件夹递归索引 | 会增加资源占用，也削弱“只读直接子项”的可预测性。 |
| 复杂动效 | 当前性能优势明显，不应为装饰性动画牺牲空闲资源。 |

## 推荐落地顺序

| 顺序 | 内容 | 验收 |
| --- | --- | --- |
| 1 | 空 Dock 引导、移除确认、文档去编辑模式化 | 新用户不读 README 也能完成首次添加；误移除有确认。 |
| 2 | 损坏项状态和重新定位 | 删除或移动目标后，Dock 项不只报错，还能恢复。 |
| 3 | 右键菜单补全和分组 | 常用单项操作不必进入设置页。 |
| 4 | 设置页按钮和路径展示优化 | Dock 项区域更清爽，路径不压迫主操作。 |
| 5 | 分组管理搜索和筛选 | 20 项以上文件夹仍能快速归类。 |
| 6 | 复杂背景可读性优化 | 深浅复杂壁纸下 Dock 边界稳定可辨。 |

## 一句话结论

下一阶段的重点不是“更多功能”，而是让用户更快开始、更敢调整、更容易恢复，并让 Dock 在复杂桌面上始终清楚可读。
