# TidyDock 优化后全面复评

日期：2026-07-05

## 结论

上一轮产品体验优化已经基本完成：首次使用、右键管理、失效目标恢复、设置页草稿文案、复杂背景可读性、Flyout 顶部信息、分组搜索筛选都已落地。

当前下一阶段重点应从“补体验入口”转向“发布硬化”：配置恢复、诊断导出、测试计划同步、多显示器验证、性能基线更新。

## P0 建议

| 方向 | 现象 | 建议 |
| --- | --- | --- |
| 配置恢复 | `ConfigService.Load()` 解析失败后直接返回默认配置，只记录日志；没有复制坏配置，也没有尝试最近备份。 | 解析失败时复制原文件为 `.broken-时间戳`，优先尝试最近自动备份；恢复失败再创建默认配置。 |
| 文档同步 | `docs/09-test-plan.md`、`docs/03-ui-spec.md`、`docs/issues/v0.2.0-backlog.md` 仍保留旧版编辑模式、旧测试项或已完成 backlog。 | 发布前清理旧叙事，把已完成项标记完成，新增 v0.2 真实测试项。 |
| 发布检查 | `docs/10-release-checklist.md` 仍指向 WPF `src/TidyDock` 构建脚本。 | 增加 WinForms v0.2 专用发布检查，命令改为 `src/TidyDock.WinForms`。 |
| 诊断反馈 | 用户遇到异常时目前只能打开配置目录或看日志，缺少一键复制诊断摘要。 | 设置页增加 `复制诊断信息`：版本、配置路径、日志路径、OS、启动耗时、内存摘要，不包含 Dock 项真实路径。 |

## P1 建议

| 方向 | 现象 | 建议 |
| --- | --- | --- |
| 性能基线 | `docs/15-performance-baseline.md` 还停留在较早 WinForms 数据；本次短测 private memory 约 15.53 MB 未归档。 | 更新 v0.2 当前基线，并补测：打开设置页、打开/关闭 Flyout、50 项 Dock、10 分钟 idle。已完成 10 分钟 idle 和 50 项 Dock 压测。 |
| 多显示器 | PRD 有显示器选择，但当前设置页主要暴露位置、外观、行为；多显示器验证未形成清单。 | 增加显示器选择入口或明确暂不做；测试 top/bottom/left/right 与任务栏位置冲突。 |
| 键盘可达性 | Dock、Flyout 多为自绘区域，鼠标路径已顺，但键盘和辅助访问弱。 | 补 Tab 顺序、Esc/Enter 行为、菜单键/Shift+F10、基础 accessibility name。 |
| 右键菜单视觉 | 功能完整，但仍是系统默认菜单，字号和玻璃 Dock 风格割裂。 | 后续可做轻量自绘菜单或放大菜单项高度；优先保证高 DPI 可读性。 |
| 设置页 Dock 项区 | 功能完整，但按钮仍偏多，用户第一次看会有密集感。 | 把低频操作折叠到 `更多`，常用保留添加、重命名、移除、管理分组。 |
| 备份导入 | 资源文件先复制，取消设置后可能留下孤立资源。 | 可接受但需清理策略：导入预览取消后提示“已导入资源未生效”，或记录待清理资源。 |

## P2 建议

| 方向 | 建议 |
| --- | --- |
| 语言设置 | `Language` 存在但当前主要是中文界面；若 v0.2 只面向中文，可暂时隐藏语言设置，避免承诺双语。 |
| Flyout 短路径 | 当前短路径仍可能偏长；窄窗口下建议只显示末两级路径，中间省略。 |
| 空 Dock 截图测试 | 现在有空 Dock 引导，但建议补一张空配置截图，作为发布视觉验收项。 |
| 日志策略 | 日志记录异常完整堆栈有利于开发，但诊断摘要应默认脱敏，避免暴露用户目录和文件名。 |
| Issue backlog | 已完成的 context menu、broken item、backup restore 应从 backlog 移到 changelog 或标记 done，避免后续重复开发。 |

## 不建议继续扩张

| 方向 | 原因 |
| --- | --- |
| 最近应用 / 最近文件 | 会引入行为记录和隐私解释成本。 |
| 运行状态指示 | 会偏向任务栏替代品。 |
| 自动分类 | 会破坏“手动整理”的产品边界。 |
| 文件夹递归索引 | 会牺牲低资源和可预测性。 |
| 复杂主题系统 | 当前视觉已经足够，继续扩主题性价比低。 |
