# v0.2.0 Issue Backlog

This file keeps issue-ready drafts for the v0.2.0 milestone. Completed items stay here only as release traceability; new work should start from the open section.

## Completed

### 1. Add Dock Item Context Menu

Status: Done

- Dock item right-click menu is item-first.
- Supports open, rename, change icon, reset icon, remove, folder Explorer open, folder open behavior, and folder group management.
- Remove is guarded by confirmation.

### 2. Add Broken Item State and Relink Flow

Status: Done

- Missing app/file/folder targets show a warning badge.
- Activation prompts relink.
- Right-click menu exposes `重新定位目标`.
- URL and Shell items are not marked as broken.

### 3. Validate and Repair Config on Load

Status: Done

- Missing fields are normalized.
- Invalid sizes, opacity, magnification and folder panel settings are clamped.
- Broken config files are preserved as `settings.broken-时间戳.json`.
- Startup tries the latest automatic backup before falling back to defaults.
- Repair and recovery decisions are written to the local log.

### 4. Add Config Backup and Restore UX

Status: Done

- Settings page can export a zip backup.
- Backup contains `settings.json`, `icons/`, and `shortcuts/`.
- Import writes into settings draft first.
- Imported config is normalized before preview or save.
- Save creates automatic backups and keeps the latest 5.

### 5. Improve Log Access and Diagnostics

Status: Done

- Settings page can open the config folder.
- Settings page can copy a diagnostics summary.
- Diagnostics include app version, startup time, config path, log path, OS, .NET, memory and handle count.
- Diagnostics do not include Dock item target paths.

### 6. Record Startup Time and Update Performance Baseline

Status: In progress

- Startup duration is recorded in local logs.
- The performance baseline document includes WinForms v0.2 measurements.
- Longer 10-minute idle and 50-item Dock measurements still need a release-candidate pass.

## Open

### 7. Automate GitHub Release Packaging

Labels: `ci`, `release`, `v0.2.0`

#### Problem

The project can build packages locally, but GitHub Releases are still manual.

#### Scope

- Add a tag-triggered GitHub Actions workflow.
- Build installer and portable zip.
- Upload artifacts to the GitHub Release.
- Keep manual local release instructions as fallback.

#### Acceptance Criteria

- Pushing a `v*` tag can produce release artifacts.
- Release workflow does not require secrets for unsigned builds.
- Failed release builds surface logs clearly.

### 8. Extended Release Hardening

Labels: `qa`, `performance`, `v0.2.0`

#### Problem

Short smoke tests pass, but release hardening still needs longer idle and larger-config coverage.

#### Scope

- 10-minute idle sample.
- 50-item Dock sample.
- Multi-monitor and taskbar edge-position pass.
- High DPI menu readability pass.

#### Acceptance Criteria

- No sustained idle CPU.
- No obvious GDI or private memory growth after repeated Flyout browsing.
- Dock positions correctly on selected display.
- Context menus remain readable on high DPI displays.
