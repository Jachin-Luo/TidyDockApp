# 开发笔记与踩坑记录

本文记录 TidyDock v0.2 WinForms 重写过程中的关键经验、踩坑点和后续开发约束。它不是更新日志；更新日志记录“做了什么”，本文记录“为什么这样做、下次要避开什么”。

## WinForms 重写方向

- v0.2 选择 WinForms + GDI+/Win32 interop，是为了降低常驻内存和窗口层级复杂度。
- 旧 WPF 版本保留为 legacy 参考，新 WinForms 配置使用 `%APPDATA%\TidyDock\winforms`，避免旧配置格式反向约束新实现。
- 低资源占用优先级高于复杂动效。动画只允许短时、一次性运行，不能有空闲状态持续刷新循环。

## 分层透明窗口

- Dock 透明必须使用 `UpdateLayeredWindow` 的 per-pixel alpha，色键透明会出现边缘色块、紫边、黑边等问题。
- `UpdateLayeredWindow` 每次提交的是一张位图，适合 Dock 这种小窗口；但不要在空闲状态持续重绘。
- Dock 和文件夹 Flyout 的动画应只改变 alpha、位置偏移或 hover scale，并在动画结束后停止 Timer。
- 复杂壁纸下的可读性优先通过“增强底座对比度”开关调高描边、阴影和内高光，不切换到 Acrylic/Mica，也不引入额外持续渲染。

## 图标加载与圆角套壳

- Shell 图标不能直接假设 HBITMAP 行方向正确。之前文件夹 Flyout 图标出现倒置和绿色杂边，根因是位图行方向和 alpha 预乘处理不完整。
- `.lnk` 图标要解析真实目标，否则会带 Windows 快捷方式箭头，且桌面快捷方式删除后 Dock 项可能失效。
- `.lnk` 和 `.url` 应复制到 v0.2 数据目录，不能依赖桌面原文件。
- `DockItem.IconPath` 是自定义图标来源；行内“圆角”开关应逐项生效。全局“包含自定义图标”只影响一键批量操作，不能阻止单个自定义图标套圆角。
- 圆角底板保持白色系、轻灰渐变和细边框，避免从图标取色导致黄底叠黄图标、上下分层或“三层感”。

## 设置页与 Dock 解耦

- 设置页目前和 Dock 共用同一个配置对象，并通过 `_apply()` 触发 Dock 重算、保存和重绘；这不是 WinForms 硬限制，而是当前实现耦合。
- 滑条拖拽会高频触发 `ValueChanged`，不能每次都同步保存和重绘 Dock，否则设置页滚动位置、焦点和布局容易被 WinForms 自动滚动影响。
- 滑条类设置应使用防抖：拖拽时只更新配置值和旁边数字，停止一小段时间后再统一预览刷新 Dock。
- 后续更理想的方案是“草稿配置 + 预览 + 确定”：设置页只修改 draft，点预览时应用到 Dock，点确定时保存。
- 用户已确认下一步采用统一的“预览 / 确定”交互：设置页修改先进入草稿态，不立即触发 Dock 重绘；点击“预览”时只刷新 Dock 供查看；点击“确定”时再写入配置并保存，关闭或取消则丢弃未确认修改。
- 这个方案优先于继续堆防抖和滚动位置恢复。原因是问题根源不只是事件频率，而是设置页修改、配置保存、Dock 重绘共用同一条即时链路。
- 独立 Dock UI 线程可以隔离设置页和 Dock，但会引入跨线程消息、托盘归属、退出顺序和 Dispose 复杂度，v0.2 暂不建议。

## 设置页 WinForms 控件坑

- 透明/半透明父子控件容易出现黑块、残影和重叠。自绘控件需要自己绘制稳定背景，不能依赖默认透明背景。
- `ListView.OwnerDraw` 中不要同时使用行级背景绘制和单元格绘制，否则鼠标悬停时可能把单元格文字盖掉。
- 表格列宽要吃满可视区域，否则右侧会出现奇怪空白。
- 避免嵌套滚动条。Dock 项表格如果放在设置页滚动容器里，表格自身应关闭内部滚动，并按项目数量自动增高。
- 原生 WinForms 滚动条在深色主题下可能突兀。当前使用 `SetWindowTheme(..., "DarkMode_Explorer")` 尝试适配；如果系统仍显示偏白，后续再考虑自绘滚动容器。

## 文件夹 Flyout

- 文件夹 Flyout 只读取直接子项，不递归扫描，不做后台索引。
- 大文件夹要按 `MaxItems` 截断并提示，避免 UI 阻塞。
- 曾存在“软件启动后首次点击文件夹较慢、再次打开明显变快”的性能问题。根因是目录枚举虽然已通过 `Task.Run` 放到后台线程，但首屏图标仍由 `FolderFlyoutForm.DrawEntryCells()` 在 UI 线程同步解析。
- 当前实现先用通用文件/文件夹占位图标完成首帧，只把可见项加入后台加载队列；图标完成后通过 32ms Timer 合并刷新，不能让每个 Shell 图标完成事件立即触发一次完整重绘。
- `.lnk` 项仍需通过 Shell COM 解析真实目标，再调用 `IShellItemImageFactory` 提取图标。后台加载保持串行，避免并发 Shell 调用造成瞬时资源峰值；切换目录时取消旧批次，并通过加载版本忽略过期刷新。
- 文件夹条目使用独立的 256 项内存 LRU，避免后台淘汰与 Dock 图标绘制共享图片对象。UI 在缓存锁内完成绘制，后台线程不能在绘制过程中释放同一张图片。
- 持久化缓存写入 `%APPDATA%\TidyDock\winforms\cache\folder-icons`，键包含路径、类型、修改时间、文件大小和图标尺寸；写入使用临时文件后原子替换，损坏缓存会删除并重新提取，磁盘缓存按最近访问时间保留约 512 项。
- Flyout 原生窗口在 `Application.Idle` 时只预创建窗口句柄，不读取任何目录；用户点击后仍按需读取文件夹内容。
- 2026-07-12 集成验证：包含 25 个快捷方式的分组文件夹在冷缓存下 `ShowFor()` 193ms 返回，后台只为首屏 12 项生成缓存；重新创建 `IconService` 后从磁盘缓存启动，`ShowFor()` 89ms 返回。该数据只用于确认加载链路已异步化，不作为不同机器上的固定性能指标。
- 不应在启动阶段预读所有文件夹内容。这样只会把延迟转移到启动阶段，并破坏“用户点击后才读取目录”的产品边界。
- Flyout 顶部不要长期展示完整路径，容易挤占信息层级；更适合展示“项目数 + 短路径”，完整含义通过按钮 tooltip 和资源管理器入口补足。
- 文件夹分组只绑定到单个文件夹 Dock 项，保存直接子项相对路径 key；它是展示层分类，不移动、不重命名、不创建真实文件夹。
- 分组第一版只在 Dock 项根目录生效；进入子文件夹后回到普通网格，避免把分组语义扩展成递归目录管理。
- 分组数量不可控，不适合使用横向 Tab；Flyout 应使用纵向分段展示，所有分组在同一页面随内容滚动。仅当存在未归类项目时展示“未分组”段。
- 分组管理弹窗右侧文件列表不能在加入/移除分组时清空重建，否则大列表会跳回顶部；应只更新行内“所属分组”文本，并保留 `TopItem`、焦点和选中状态。
- 分组管理的批量操作应优先使用复选框选择，降低 Ctrl/Shift 多选的学习成本；如果没有勾选项，再兼容 `SelectedItems`。
- 批量加入或移出分组后要自动清空勾选，避免用户误以为操作未结束，或下一次继续作用在上一批项目上。
- 分组管理里的搜索、只看未分组、只看当前分组都只过滤当前已读取的直接子项，不能触发递归扫描或后台索引。
- 滚动绘制必须设置 GDI 裁剪区域；`TextRenderer.DrawText` 在某些情况下不完全服从裁剪，改用 `Graphics.DrawString` 更稳。
- 快速滚轮滚动时要留底部安全边距，避免文字或图标轻微越界。
- Flyout 关闭入口要统一：Esc、关闭按钮、失焦和鼠标离开延迟关闭都走同一套关闭动画。

## Dock 交互与布局

- Dock 是手动管理的启动器，不是任务栏替代品。不做运行中小圆点、进程监控、badge、窗口切换或最近应用。
- 拖拽排序默认关闭，避免误触。
- 分隔符不能占完整图标槽位，应使用窄槽位，并同步调整 Dock 总宽度、命中区域和 hover 计算。
- Hover 放大要使用短时 ease-out 过渡；中心图标放大，邻近图标轻微放大，不做持续动画循环。
- Dock 右键菜单用于单项快速管理，应把当前项的打开、重命名、图标、打开方式、分组和移除放在前面；全局添加入口放在后面。
- Dock 右键入口仍属于运行时即时管理，和设置页草稿流程不同；用户在 Dock 上直接改的内容应立即保存。

- 每次 UI 或行为修改后，优先跑：

```powershell
dotnet build .\src\TidyDock.WinForms\TidyDock.WinForms.csproj -c Release -warnaserror
```

## 设置页草稿配置落地记录

- 设置页不再持有运行中的 Dock 配置对象，而是持有打开设置时克隆出的 `draftConfig`；打开时同时保留一份 `originalConfig` 快照。
- 所有设置页控件只允许修改草稿。滑条、开关、Dock 项表格、文件夹分组管理都不能直接调用保存或 Dock 重绘入口。
- Dock 只暴露三个设置页入口：`PreviewSettings` 临时应用草稿但不保存，`CommitSettings` 应用并保存，`CancelSettings` 恢复打开设置前快照但不保存。
- 如果用户点过“预览”，再点“取消”或直接关闭窗口，必须把运行中的 Dock 恢复到 `originalConfig`；这是草稿流程最容易漏掉的状态。
- `跟随 Windows 启动` 是系统启动项，不属于 `AppConfig`，仍然即时调用 `StartupService.SetEnabled()`。
- 后续新增设置项时默认只写草稿；除非是 Dock 外部入口，例如拖拽文件到 Dock、Dock 右键删除、托盘菜单行为，才继续使用即时保存入口。

## 设置页状态反馈与卸载配置保留

- 草稿页需要同时比较三份配置：打开设置前的 `originalConfig`、当前草稿 `_config`、上次预览 `_lastPreviewConfig`。状态文本和按钮启用都应从这三者的差异推导，不能靠单个布尔值猜测。
- 如果当前草稿等于打开前配置，但上次预览不是打开前配置，仍然属于“有未预览修改”：用户需要再点一次预览，才能把运行中的 Dock 恢复到草稿状态。
- 关闭设置页时，只要草稿未保存或曾经预览过未保存状态，就要确认放弃；确认后必须调用取消入口恢复打开设置前的 Dock。
- 卸载默认只删除程序目录、开始菜单快捷方式和启动项，不删除 `%APPDATA%\TidyDock\winforms`，这样重装可以恢复 Dock 项、自定义图标、托管快捷方式和分组配置。
- 清除用户配置必须显式使用 `Uninstall-CurrentUser.ps1 -RemoveUserData` 或开始菜单“卸载并清除配置 TidyDock”，避免普通卸载误删用户数据。

## 配置导出、导入与自动备份

- 用户可恢复能力不能只依赖“卸载不删配置”，还需要显式导出和导入。备份包应至少包含 `settings.json`、`icons/` 和 `shortcuts/`，否则自定义图标和托管快捷方式迁移后会失效。
- 导入备份时只把 `settings.json` 写入设置页草稿，仍然遵守“预览 / 确定 / 取消”流程；资源文件可以先复制进数据目录，取消设置时最多留下孤立资源文件，不影响当前 Dock。
- 自动备份应在保存配置前创建，保留最近 5 份即可；避免无限增长，也避免只保留单个 `.bak` 导致用户无法回到更早状态。
- 恢复最近备份本质上也是一次导入草稿，不能绕过设置页确认流程直接保存。
- 主配置损坏时不能直接覆盖成默认配置。必须先复制为 `settings.broken-时间戳.json`，再尝试最近自动备份；只有恢复失败才写入默认配置。
- 备份导入进入草稿前也要执行配置规范化，避免极端数值或缺失字段进入预览流程。

## 发布硬化记录

- WinForms v0.2 portable 改为 self-contained 单文件发布，优先保证干净机器能启动；代价是包体积明显增大。
- 设置页诊断摘要默认只包含版本、启动耗时、OS、.NET、配置路径、日志路径、数量、内存和句柄，不包含 Dock 项真实目标路径。
- 图标缓存必须有上限。文件夹 Flyout 会按需加载大量文件图标，如果缓存无限增长，常驻程序会随着浏览历史持续占用资源。
- 文件夹读取达到 `MaxItems + 1` 后应停止枚举。截断提示比完整扫描大目录更符合低资源边界。
- 多显示器支持已有 `DockSettings.Display` 和布局服务，设置页需要暴露入口，并继续以主屏幕为默认值。
- 发布硬化压测脚本必须备份并恢复 `%APPDATA%\TidyDock\winforms\settings.json`。50 项 Dock 采样可以临时写入测试配置，但 finally 中必须恢复用户真实配置。
- 10 分钟 idle 和 50 项 Dock 采样结果显示 private memory 和 handle count 没有持续增长，后续每个 release candidate 都应至少跑一次。
- GitHub Release 自动化只复用本地已验证脚本，避免 CI 和本地发布走两套逻辑；`v*` tag 触发后构建 WinForms v0.2 installer、portable zip 和 `SHA256SUMS.txt`。
- unsigned release 不需要额外 secret，使用 GitHub 内置 `GITHUB_TOKEN` 创建或更新 Release；代码签名以后单独作为发布增强项处理。
- Shell COM 对象不能只依赖 GC 回收。`.lnk` 解析的 `ShellLink` 和 `IShellItemImageFactory` 应在使用后 `FinalReleaseComObject`，否则真实配置 idle 采样中可能出现几分钟后 private memory 和 handle 突增，容易被误判为持续泄漏。

## 键盘可达性记录

- Dock 不作为任务栏替代品，但仍应提供基础键盘入口：`Menu/Shift+F10` 打开菜单，`Enter/Space` 打开悬停项，`Ctrl+,` 打开设置。
- 设置页使用自绘按钮，不能依赖 WinForms 默认 `AcceptButton`；需要在 `ProcessCmdKey` 中显式处理 `Esc`、`Ctrl+P`、`Ctrl+S`。
- 文件夹 Flyout 是自绘面板，方向键只在当前可见项中移动，避免为了键盘导航引入复杂虚拟焦点和持续重绘。

## 产品体验 P0 优化记录

- 空 Dock 引导只在没有真实启动项时显示；默认设置项不应挡住首次使用入口。引导入口直接调用现有添加和设置流程，避免新增 onboarding 状态。
- 右键移除必须确认，并明确“不删除原文件”，因为 Dock 项是用户整理成果，误删会造成配置损失。
- 目标不存在不能只报错；Dock 上应有视觉警示，并提供重新定位路径。重新定位后立即保存，保持 Dock 右键入口的即时管理语义。
- 设置页草稿按钮文案应描述行为，不只写“预览 / 确定”。当前统一使用 `预览到 Dock` 和 `保存并关闭`。
- 文档应描述“右键快速管理 + 设置页批量管理”，不要继续沿用旧 WPF 的“编辑模式”叙事。

## 复评精致度优化记录

- 设置页目标列不能暴露托管快捷方式的内部文件名。`.lnk` 应优先解析真实目标并显示目标名称，托管路径只放 tooltip。
- 设置页 Dock 项操作按钮要跟随选择状态；`管理分组` 只能在选中文件夹项时启用，避免用户点了才发现不可操作。
- 数据与备份区的诊断入口应和同类按钮放在一起，避免被固定 footer 挤到边缘。
- 分组管理列表列宽应跟随窗口变化，筛选区允许换行，优先避免横向滚动条和拥挤文案。
- 右键菜单属于高频入口，中文长标签需要更大的最小宽度和行高；先用 ToolStrip 尺寸优化，不引入复杂自绘菜单。
- `ContextMenuStrip` 在暗色主题下不能只设置 `BackColor` / `ForeColor`，子菜单、箭头和 hover 文本仍可能走系统默认黑字绘制；应统一使用主题化 `ToolStripProfessionalRenderer`，并在 `OnRenderItemText` 中显式垂直居中绘制文字。
- Flyout 不新增独立对比度设置，复用 `HighContrastDock`，保持设置面板简单。
- `ContextMenuStrip.Closed` 里不要同步 `Dispose()` 当前菜单；WinForms 的 `ToolStripManager` 可能还在处理关闭流程，会触发 `ObjectDisposedException` 并导致进程退出。需要释放时使用 `BeginInvoke` 延迟到当前消息处理之后。

## 2026-10-09 设置与交互优化

- 设置由固定宽度长页改为五个分类标签，保留原有分类名称；内容和表格列宽跟随窗口调整，Dock 项列表按可用高度限制行数，避免操作栏被长列表挤出可视区。
- Dock 项支持按名称、目标和类型搜索，移除可逐次撤销。过滤后的移动和移除必须根据选中对象查找配置索引，不能把可见行号当作配置索引。
- 主题重建释放旧控件和 ImageList，保留分类、搜索词和选中项；隐藏分类的 ListView 恢复选择前必须创建句柄，否则选择状态可能丢失。
- 取消按钮和 Escape 统一经过关闭确认；搜索框内有文字时 Escape 先清空搜索。保存按钮在草稿等于原始值时仍可用，允许用户预览后恢复原值并保存关闭。
- 按钮、开关和滑条补齐键盘、焦点和禁用状态，以及辅助功能默认操作或数值状态；滑条捕获鼠标，失去捕获时停止拖动。
- 深色主题强调色配深色文字，满足普通文字 4.5:1 对比度；悬停放大滑条上限与配置规范化的 1.8 倍保持一致。
- 新增 `tests/TidyDock.UiTests`，使用合成配置和内存回调测试行为，并渲染深浅主题、五个分类、三种窗口宽度。测试不读写用户设置；离屏图像不能替代混合 DPI 显示器和真实辅助技术的人工验收。

## 2026-10-10 传统磨砂玻璃

- Dock 和文件夹浮窗保留原有分层绘制，由独立、不可激活的合成窗口提供背景模糊。合成窗口随主体移动、隐藏和销毁，位于图标与桌面之间，不扩大提示文字和放大图标的玻璃区域。
- 使用 Windows 的可选 AccentPolicy 扩展模拟传统磨砂材质，不是 Apple 原生材质，也不实现 Liquid Glass 折射。API 不可用、旧系统、系统透明关闭或高对比度时使用实色底板。
- 原生 Acrylic 在部分 Windows 版本上会在自定义圆角区域外绘制底色；合成器层保持接近无色，实际半透明底色和细亮边由前景圆角遮罩绘制。
- 模糊由系统合成，不截取桌面、不缓存用户屏幕内容、不增加常驻轮询计时器。浅深主题改为中性灰白，沿用原有青绿色交互强调色。
- 设置页原生文字无法可靠参与整窗透明合成，保留实色内容和中性配色，不以丢字换取透底效果。
- `--glass-preview` 使用受控条纹背景检查真实合成效果，并用独立数据目录运行 Dock/浮窗，避免改写用户配置。离屏 `DrawToBitmap` 无法验证系统背景模糊。

## 2026-10-10 Dock 磨砂闪烁修复

- 合成背景同步必须幂等：尺寸、Owner 和 TopMost 未变时不重复赋值；背景已经紧邻前景下方时不再调用 `SetWindowPos`。原实现静态重绘 30 帧会触发 30 次背景重定位，修复后为 0。
- 圆角区域在显示前设置；背景的 `WM_WINDOWPOSCHANGING` 约束显示和层级变更，避免先升到图标上方再降回去。保留不可激活和输入穿透行为。
- Dock 和文件夹浮窗的分层渲染增加重入保护，材质状态变化在当前帧内生效，不因同步 `ActiveChanged` 回调重复绘制。
- `--glass-preview` 新增原生位置消息监测，覆盖移动、尺寸、隐藏恢复、置顶和最小化恢复。浅深主题分别检测 Dock 悬停及浮窗连续 60 帧：背景重定位为 0，底部固定采样区域最大平均 RGB 差为 0/255；原有背景模糊检查仍通过。
